# iOS 首版验证与后续 Tickets

日期：2026-10-28。源功能基线：`eaa141f`。目标：`ios/GuitarLearn.xcodeproj`。

用户使用 iPhone，先自用学习，之后可能公开发布。本批次是先验证原生音频能力的第一版，不等于课程、曲库已迁入 App。

## 环境与结论边界

当前 Mac 为 macOS 15.7.9，Swift 6.1.2，开发工具指向 `/Library/Developer/CommandLineTools`；未找到完整 Xcode，只有 macOS SDK，没有 iOS SDK。

因此 **iOS 专属代码编译、模拟器启动、签名安装、iPhone UI、真琴音高精度、实际节拍发声时序均待验收**。macOS 类型检查与合成 PCM 测试不能替代以上项目。没有生成 IPA，也没有提交 TestFlight / App Store。

## 自动检查

入口：`pnpm ios:check`。原生核心测试不访问麦克风或播放声音。

本次执行结果：4 组 Node 测试通过，5,331 项原生核心断言通过，会话生命周期检查通过；工程引用、plist 与 macOS SDK 类型检查通过。Web `pnpm typecheck` / `pnpm lint` 通过。**iOS 构建显示 PENDING；两项连续相位 E2 精度检查显示 ACCURACY GATE FAILED。** 检查命令成功表示移植一致性与软件逻辑通过，不表示音频精度或可发布状态通过。

- 生成物核对：版本锁定 `@kretoffer/guitar-audio-kit@0.0.2`，校验打包脚本与资源一致。
- Node：160 次目标局部音域的检测结果与发布库一致；包含静音、错误音域，保留原库误差；300 毫秒稳定窗口、断流、静音、音高变化和非法输入。
- Swift / JavaScriptCore：执行 App 自带的真实 JS 资源；44.1 / 48 kHz 合成 E2 输入、清空检测状态、静音。
- PCM 输入：256 / 1024 / 2048 / 4096 / 4800 帧不同缓冲大小，4096 窗口、2048 步进、时间戳和丢帧重置。
- PCM 节拍：44.1 / 48 kHz、30–240 每个整数 BPM，四拍波形、循环边界、拍号位置、每分钟采样取整误差 <1 毫秒。此为数学检查，不是发声测量。
- 会话：以假麦克风验证迟到授权、拒绝、取消、权限弹框、后台、迟到读数、旧请求失效、输入失败清理。系统权限弹框本身仍需真机检查。
- 配置文件检查和当前 macOS SDK 可见源码的 Swift 类型检查。若有 iOS SDK，追加无签名模拟器构建；本机缺少该 SDK，保留待办。
