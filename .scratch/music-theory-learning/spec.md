# 吉他乐理学习：随课理解、集中复习与分阶段进阶

Status: ready-for-agent

日期：2026-11-10

## Problem Statement

零基础学习者目前可以跟随课程辨认吉他、调音、读 TAB、弹旋律和练习伴奏，但难以解释自己正在弹什么，也难以将所学迁移到陌生歌曲。已有课程介绍了拍子、小节、长音、休止和基本识谱，但音名、音级、指板位置、音阶与和弦构成之间缺少连贯的解释。

用户需要逐步建立理解，从看懂当前练习，到读新谱、移调，再到理解和声并尝试编配；同时，理论学习不应阻断拿琴练习。

## Solution

建立“随弹奏课学习一个相关知识点 + 集中复习”的基础乐理学习路径。每个知识点包含解释、图示或主动播放的合成示范，以及小任务和答案解释。支持选择／判断、点选指板或谱面、听示范后辨认三类任务；涉及拿琴操作的部分提供自查提示。

全部范围分三阶段交付，每阶段在 Web 和微信小程序同步提供相同内容与状态含义。iOS 在迁入完整课程时接入。

| 阶段 | 内容 | 学习成果 |
| --- | --- | --- |
| 一：看懂正在弹什么 | 音名、指板、时值、音级、C 大调、基础音程、大小三和弦 | 能解释简单旋律与和弦 |
| 二：读谱与迁移 | 五线谱基础到常用读谱、其他常用调、调号、移调、顺阶和弦与常见进行 | 能把熟悉的知识用到新歌曲 |
| 三：理解与编配 | 七和弦、和弦功能、转位、属和弦扩展、借用和弦、旋律配和弦与伴奏编配 | 能为简单旋律制作并解释自己的伴奏 |

第三阶段以具体歌曲案例限定复杂和声的深度，不承诺覆盖所有和声体系。先交付第一阶段，再依次推进后续阶段。

## User Stories

1. As a 吉他初学者, I want 在弹奏课用到概念时进入对应乐理内容, so that 我能理解当前动作背后的含义。
2. As a 吉他初学者, I want 从乐理内容返回原弹奏课的位置, so that 我能接着练琴。
3. As a 吉他初学者, I want 在集中复习入口找到已交付的知识点, so that 我不用逐课寻找解释。
4. As a 吉他初学者, I want 按阶段和学习顺序浏览内容, so that 我知道从哪里开始及下一步学什么。
5. As a 吉他初学者, I want 区分音名、音级、TAB 品位和手指编号, so that 我不会把不同数字误认为同一含义。
6. As a 吉他初学者, I want 认识 A–G 与升降号, so that 我能理解调音和曲谱中的音名。
7. As a 吉他初学者, I want 理解半音、全音与指板一品的关系, so that 我能理解相邻品位的音高变化。
8. As a 吉他初学者, I want 将音名对应到入门练习中的指板位置, so that 我能将抽象概念用于琴上。
9. As a 吉他初学者, I want 理解拍子、小节、基础时值、休止与细分, so that 我知道何时发声、延长和停顿。
10. As a 吉他初学者, I want 用 C 大调理解音阶与简谱音级, so that 我知道简谱数字表达什么。
11. As a 吉他初学者, I want 理解基础音程, so that 我能描述两个音之间的关系。
12. As a 吉他初学者, I want 理解根音及大小三和弦的基本构成, so that 我能解释 C、Am、Em 等名称。
13. As a 学习新歌曲的用户, I want 逐步学习五线谱常用读谱知识, so that 我能理解更多形式的曲谱。
14. As a 学习新歌曲的用户, I want 理解其他常用调与调号, so that 我能把 C 大调所学迁移到其他调。
15. As a 学习新歌曲的用户, I want 通过具体练习理解移调, so that 我能理解旋律或伴奏改变调后的关系。
16. As a 学习新歌曲的用户, I want 理解顺阶和弦与常见进行, so that 我能发现歌曲伴奏的规律。
17. As a 进阶学习者, I want 用歌曲案例理解七和弦、功能与转位, so that 我能解释更多伴奏选择。
18. As a 进阶学习者, I want 学习属和弦扩展与借用和弦, so that 我能理解常见进阶和声用法。
19. As a 进阶学习者, I want 为简单旋律选择和弦并设计伴奏, so that 我能开始制作自己的编配。
20. As a 进阶学习者, I want 看到编配案例的选择理由, so that 我能理解同一旋律可能有不同合理处理。
21. As a 学习者, I want 用选择或判断题检查理解, so that 我能及时发现概念混淆。
22. As a 学习者, I want 点选指板或谱面回答问题, so that 我能将概念与实际位置关联。
23. As a 学习者, I want 主动播放合成示范后用选项完成听辨, so that 我能将文字知识与听觉联系起来。
24. As a 学习者, I want 每个小任务提供答案解释, so that 我知道为什么正确或错误。
25. As a 学习者, I want 无限次重试小任务, so that 我能在理解后再通过练习。
26. As a 学习者, I want 跳过小任务并继续阅读或练琴, so that 理论题不会阻断学习。
27. As a 学习者, I want 区分已阅读与练习通过, so that 我知道哪些内容仍需练习。
28. As a 学习者, I want 全部小任务答对后才获得该知识点的练习通过状态, so that 状态反映已完成的知识练习。
29. As a 学习者, I want 拿琴操作的自查单独表达, so that 我不会将自查误认为系统验证了演奏能力。
30. As a 学习者, I want 退出后重新进入仍能看到本设备已保存的学习状态, so that 我能继续复习。
31. As a 已有用户, I want 原课程位置、自查和完成记录继续有效, so that 新增乐理不会破坏既有学习进度。
32. As a 学习者, I want 保存失败或进度无法读取时得到准确提示, so that 我不会误以为记录已安全保存。
33. As a 微信小程序用户, I want 获得与 Web 同阶段的内容和练习规则, so that 平台差异不会改变学习含义。
34. As a 手机学习者, I want 在短屏上看清题目、选项与反馈并操作指板或谱面, so that 我能顺畅完成学习。
35. As a 学习者, I want 离开内容时示范停止且不自动申请麦克风, so that 音频行为符合我的主动操作。

## Implementation Decisions

- 保留现有弹奏课程及其稳定标识，扩展相关知识点入口与返回原课位置的交互；不重新定义原课完成规则。
- 增加乐理知识内容、集中复习呈现、小任务交互和乐理学习状态。按用户可见职责划分即可，不要求为每种题型建立独立服务或框架。
- 优先沿用 Web 内容生成微信小程序内容的现有方式，以相同来源维护课程内容和任务答案，平台分别适配交互及本地存储。
- 知识点与任务使用稳定标识，阶段顺序用于学习引导。知识点与相关弹奏课建立关联；不能依赖数组位置识别已通过内容。
- 乐理学习状态在语义上独立于弹奏课进度与练习记录；沿用本地持久化模式，不增加后端、账号或云同步。
- “已阅读”表示用户完成该知识点阅读；跳过小任务最多记录已阅读。“练习通过”表示该知识点的全部小任务均已答对，允许多次尝试；不要求首次或连续答对。
- 拿琴自查与知识任务通过分开表达，不作为自动检测结果。乐理状态不作为弹奏课程解锁条件。
- 三类题型均给出可理解的结果与解释，错误后可重试或复习，跳过后可回来补做。编配案例存在多种合理答案时，解释示例理由，不宣称唯一正确编配。
- 听辨采用主动播放合成示范和选项作答，沿用已有音频生命周期做法；离开当前内容或切到后台时停止，不自动播放或收音。
- 新状态需兼容旧数据缺少乐理字段的情况；不得清空原课程、自查或完成记录。延续现有保存失败可重试、损坏记录不静默覆盖的行为。
- Web 与微信提供相同内容和状态规则，但设备与平台的本地进度各自保存，不承诺相互同步。iOS 的本次即时改动不在交付范围内。
- 每个阶段独立验收：第一阶段覆盖四组基础内容及基础音程，第二、三阶段依次扩展，不要求一次性交付全部范围。
- 上述状态持久化、兼容和音频退出行为是依据现有产品模式补充的实现约束；不是新增云端能力或演奏检测承诺。

## Testing Decisions

- 用户已确认沿用现有高层测试入口：Web 用 Playwright 验证完整学习流程；微信沿用页面行为测试，并补开发者工具或真机验收。测试关注用户可见行为，不新增麦克风判定。
- Web 以“弹奏课进入相关乐理 → 阅读／作答／跳过／重试 → 查看解释 → 返回原课 → 集中复习 → 刷新恢复进度”为主要验收流程，尽量复用一个学习流程入口覆盖跨模块行为。
- 沿用既有学习课程、扩展学习与曲库测试中通过可访问名称操作页面、主动播放示范、返回原步骤和刷新恢复进度的先例；不以组件内部状态或函数调用次数作为功能成功依据。
- 微信沿用现有页面实例及存储适配边界，验证内容导航、任务交互、状态保存和返回原课。此类测试不能证明原生渲染、点击区域与实际音频效果，后者需开发者工具或真机证据。
- 覆盖三类任务的正确、错误、解释、跳过及重试路径；错题或跳过不能标记为练习通过，补齐所有任务后可以通过，且不阻断弹奏课。
- 验证已阅读、练习通过和拿琴自查的显示含义，避免显示成系统已验证演奏达标。
- 验证旧课程进度兼容、保存失败提示与重试、损坏数据不被静默覆盖。确认新增乐理操作不改变原练习记录。
- 验证课程与集中复习入口引用同一知识点、Web 和微信生成内容一致、知识点与任务标识及答案引用有效。仅在高层测试无法清晰定位内容错误时补充数据一致性检查。
- 验证示范主动启动、离开和后台停止、不申请麦克风；自动化合成音频测试不视为用户听觉辨认或实际演奏达标的证据。
- 手机短屏验收题目、选项、解释及指板／谱面点选可操作性；Web 检查键盘可操作与可访问名称。参考已有短屏学习页面验证方式。
- 每阶段检查内容与学习成果对应，尤其区分音名、音级、品位、手指编号；用可复核示例检查时值、音程与和弦解释。进阶编配检查案例理由合理，不将单一编配答案当作唯一标准。
- 执行与改动对应的类型、静态检查、构建、Web 学习测试及微信内容、页面和模板检查；不为本次纯规格发布运行产品测试。

## Out of Scope

- 本次发布规格不等于开始实现，也不发布未经用户批准颗粒度与依赖的实现 tickets。
- 首阶段不交付第二、三阶段内容；这些内容保留在完整路线内，不被删除。
- 不新增账号、后端、数据库、跨平台云同步或学习进度备份格式扩展。
- 不新增麦克风听辨评分、手型识别、整曲演奏自动评分、自动编配或 AI 对话。
- 不以乐理测验强制解锁弹奏课，不将知识题通过或演奏自查宣传为已掌握演奏技能。
- 不在当前 iOS 音频验证版中立即实现课程，不将 Web 或微信测试结论当作 iOS 已验收证据。
- 不制作覆盖所有和声体系的百科课程，不承诺外部考级、证书或原唱录音。
