# Guitar Learn MVP 规格

Status: ready-for-agent

日期：2026-10-25（Asia/Shanghai）。类型：MVP 总规格。执行状态：仅规格生成，尚未授权开始实现。

## Problem Statement

吉他初学者需要在浏览器中完成“调音 → 跟节拍 → 看和弦 → 检查按弦”的练习闭环。用户需要知道当前目标弦、实际发出的音和偏差，理解和弦的固定指法，并通过逐弦弹奏检查音高是否符合目标。拿着吉他时，手机触屏上的读数、状态和下一步操作必须清晰。

用户还需要保存自定义和弦与练习记录，能够查看、删除、备份和手动迁移；必须明确知道数据只存在当前浏览器，以及中断、未识别、错音和保存失败各自意味着什么。

“按对”只表示音高符合目标指法，不表示已经验证实际发声弦、品位、具体手指、手型或消音效果。

## Solution

提供移动端优先、桌面兼容的浏览器练习工作台，只包含调音器、节拍器、和弦库和逐弦和弦检测四个模块，并配套本地设置、练习记录、独立的和弦与记录 JSON 文件管理。

全部音频检测在浏览器执行，全部持久数据保存在 localStorage，无账号、后端数据库或云同步。统一使用标准调弦、无变调夹及可设置的 A4 基准音。用户主动启动音频功能，应用清楚区分等待、有效结果、中断、已保存和未保存。

UI 本轮确定行为约束和验收标准。视觉细节为**待设计确认**，设计稿未完成不阻塞规格生成；用户授权实现后可先使用临时视觉基线，正式视觉验收待设计稿确认。

## User Stories

1. 作为吉他初学者，我希望在手机触屏和桌面浏览器上使用四个模块，以便在不同练习环境中完成同一练习闭环。
2. 作为初次使用者，我希望页面不会自动开启麦克风或播放声音，以便主动决定何时开始。
3. 作为调音用户，我希望手动选择目标弦并同时看到弦号和目标音，以便明确正在调整哪根弦。
4. 作为调音用户，我希望看到实际音名、八度和相对目标的音分偏差，以便区分低音 E2 与高音 E4。
5. 作为调音用户，我希望分别看到已调准、调高、调低及偏离过大的提示，以便采取合适的调整动作。
6. 作为调音用户，我希望六根标准空弦都能被可靠识别，尤其是 E2，以便完成整把琴的调音。
7. 作为练习者，我希望设置 A4 基准音并一键恢复 440 Hz，以便使调音、参考音和检测采用同一基准。
8. 作为逐弦检测用户，我希望本轮期间基准音保持锁定，以便各弦结果具有一致依据。
9. 作为节拍练习者，我希望通过数值输入和加减按钮调整 30–240 BPM，以便匹配当前练习速度。
10. 作为节拍练习者，我希望选择每小节 2、3、4 拍并识别第一拍重音，以便掌握小节位置。
11. 作为节拍练习者，我希望选择四分、八分、十六分细分，以便练习不同节奏密度。
12. 作为节拍练习者，我希望关闭 click 后仍能看到完整视觉脉冲，以便安静练习。
13. 作为节拍练习者，我希望运行中修改参数时在下一小节统一生效并收到提示，以便节奏变化可预期。
14. 作为节拍练习者，我希望回到页面后手动从第一拍继续，以便不遇到后台积压的补播节拍。
15. 作为初学者，我希望查看十个基础开放和弦的固定指法，以便学习常用和弦。
16. 作为初学者，我希望播放整和弦和指定单弦的合成参考音，以便对照目标音高。
17. 作为练习者，我希望知道参考音是合成音色，以便正确理解其用途。
18. 作为初学者，我希望显示或隐藏手指编号，以便按当前学习需要查看提示。
19. 作为左手持琴用户，我希望镜像显示指法图并保留弦号，以便读懂指法而不改变资料与检测顺序。
20. 作为练习者，我希望新增和编辑自定义和弦，包括高把位和横按资料，以便练习内置库以外的指法。
21. 作为练习者，我希望复制内置和弦后修改，以便保留基础库并制作自己的变体。
22. 作为练习者，我希望输入错误的弦值、手指或横按资料时得到具体提示，以便修正资料后保存。
23. 作为练习者，我希望同名资料被自动区分而不覆盖，以便保留已有和弦。
24. 作为练习者，我希望确认后删除自定义和弦，以便整理自己的和弦库。
25. 作为练习者，我希望一次导入多个本应用格式的和弦，以便方便地迁移或分享。
26. 作为练习者，我希望无效和弦文件整份拒绝并指出问题，以便避免只导入一部分而难以核对。
27. 作为练习者，我希望一键导出全部自定义和弦并重新导入，以便备份和手动迁移。
28. 作为逐弦检测用户，我希望从内置或自定义和弦选择目标，以便展示、试听和检测共用同一套指法。
29. 作为逐弦检测用户，我希望按第 6→1 弦依次检查并跳过“不弹”的弦，以便按明确步骤练习。
30. 作为逐弦检测用户，我希望静音、噪声或不稳定声音只提示等待或重弹，以便不会被误判为音高不符。
31. 作为逐弦检测用户，我希望结果明确区分音高符合目标和音高不符，并要求八度正确，以便识别有效的音高差异。
32. 作为逐弦检测用户，我希望得到对错结果后由自己点击下一弦，以便有时间阅读并调整。
33. 作为逐弦检测用户，我希望重测当前弦并采用最近一次有效结果，以便纠正错误。
34. 作为逐弦检测用户，我希望所有应发声弦都有结果后手动完成本轮，以便自行决定何时保存。
35. 作为逐弦检测用户，我希望错音也能保存在完成记录中，以便回顾真实练习结果。
36. 作为逐弦检测用户，我希望退出、切换目标或被中断时知道本轮没有保存，以便不误以为已有记录。
37. 作为练习者，我希望麦克风检测期间暂停应用自身声音，以便降低 click 和参考音对检测的干扰。
38. 作为练习者，我希望检测结束后手动恢复节拍器声音或重新播放参考音，以便声音不会突然自动恢复。
39. 作为练习者，我希望麦克风被拒绝、不可用或断开时看到原因和重试入口，以便恢复检测并继续使用其他功能。
40. 作为练习者，我希望切到后台时停止收音并释放麦克风，以便明确检测已停止。
41. 作为练习者，我希望重新打开应用后恢复个人设置但不自动启动音频，以便保留偏好并主动开始。
42. 作为练习者，我希望按时间倒序查看练习记录，并查看每次的指法、基准音和逐弦结果，以便回顾练习。
43. 作为练习者，我希望旧记录保留练习当时的名称和指法，以便和弦编辑或删除后仍能正确理解历史结果。
44. 作为练习者，我希望独立备份和恢复练习记录，以便不依赖和弦库文件找回练习历史。
45. 作为练习者，我希望重复恢复不会增加重复记录，冲突会整份拒绝，以便保持记录可信。
46. 作为练习者，我希望恢复记录不自动新增和弦，以便两个资料集合保持可控。
47. 作为练习者，我希望确认后删除单条或全部记录，以便自行管理本地空间。
48. 作为练习者，我希望记录不自动过期，以便由自己决定保留多久。
49. 作为练习者，我希望保存失败时保留本次结果或编辑内容，并有导出、清理或重试入口，以便不丢失当前工作。
50. 作为练习者，我希望清楚看到数据只保存在当前浏览器的提示，以便提前备份并理解换设备或清理网站数据的影响。

## Implementation Decisions

### 需求基线与实现边界

- 依据已确认的 Q1–Q69；Q62 取代原 Q49 的浏览器范围并扩充 Q50 的设备范围，Q65 限定 Q29 的方向提示。遵循领域术语“标准调弦”“基准音”“自定义和弦”“逐弦和弦检测”“练习记录”“按对”。
- 当前仓库只有需求、领域术语与设计材料，没有应用代码、可复用接口、测试或 ADR；规格不宣称已有实现或验证证据。
- 技术栈为 React、TypeScript、Vite、shadcn/ui、Tailwind。音高检测使用 @kretoffer/guitar-audio-kit，可使用其底层接口并配置检测音域；不自行实现 FFT。库的实际能力必须实测。
- 职责划分为四个用户模块、共用音频协调、共用音高规则及集中本地读写。它们是职责边界，不要求建立独立包或多层框架。
- 音高规则统一处理标准空弦、品位与目标频率、实际音名和八度、音分偏差及容差。基准音默认 A4 = 440 Hz，范围 430–450 Hz，整数步长 1 Hz，采用十二平均律；正偏差代表高于目标，负偏差代表低于目标。
- 只支持标准调弦，第 6→1 弦依次 E2、A2、D3、G3、B3、E4；无变调夹。同一音高可能来自其他弦，应用不推断实际发声位置。

### 调音器行为与验收（Q23–Q29、Q51、Q58、Q65–Q67）

| 编号 | 行为约束及验收标准 |
| --- | --- |
| T01 | 初始目标第 6 弦 E2；用户可选择全部六根弦。显示当前目标弦号、目标音、有效实际音名及八度、相对目标的带符号音分偏差。 |
| T02 | 有效结果偏差在 −5 至 +5 音分内，含边界，显示“已调准”；低于 −5 且不低于 −100 提示“调高”，高于 +5 且不高于 +100 提示“调低”；保留偏差数值。 |
| T03 | 偏差绝对值大于 100 音分时，显示“偏离目标较大，请核对目标弦与调弦状态”，保留实际音名及偏差，停止显示调高或调低指令；回到范围内再按 T02 处理。 |
| T04 | 静音、不稳定或无法可靠识别时显示等待／请单独重弹，不把旧结果当作当前有效判断；不能在 1 秒内识别时继续等待，不强行判定。 |
| T05 | 六根空弦均通过真实收音验收，包括略高、略低时方向正确；E2 为重点，不接受只在合成输入下通过。 |

### 节拍器行为与验收（Q31–Q38、Q68）

| 编号 | 行为约束及验收标准 |
| --- | --- |
| M01 | BPM 默认 80，可输入及加减调整，范围 30–240，步长 1；越界或无效输入提示有效范围，不应用无效参数。 |
| M02 | 每小节可选 2、3、4 拍，默认 4；第一拍 click 音高不同，视觉突出，并显示当前拍位置。 |
| M03 | 四分、八分、十六分细分每拍分别产生 1、2、4 次 click；BPM 始终表示每分钟主拍数。视觉脉冲跟随每次细分，区分主拍、细分和小节第一拍。 |
| M04 | click 为实时合成短音。首次声音开关开启，但打开页面不启动；点击开始后运行，声音关闭时视觉节奏不变。 |
| M05 | 停止时参数修改立即生效；运行中 BPM、拍数、细分统一在下一小节第一拍生效，并显示“下一小节应用”，不能半小节混用新旧规则。 |
| M06 | 前台在 30、80、240 BPM 各连续运行 60 秒，覆盖十六分细分，累计节拍时间偏差不超过 100 毫秒，无漏拍或突然连发，视觉与声音对应。 |
| M07 | 页面进入后台暂停；返回后不自动继续，用户手动继续时从小节第一拍开始，不补播后台期间的节拍。 |

### 和弦资料与和弦库（Q3–Q10、Q13、Q41–Q45、Q52、Q56–Q57）

- 内置 C、D、E、G、A、Am、Dm、Em、A7、D7 共十个开放和弦，每个一种固定指法，提供手指编号。内置资料不可修改或删除，可复制为自定义和弦。
- 第 6→1 弦的数据顺序固定。每弦允许“不弹”、空弦或第 1–24 品。名称不可为空，必须恰有六根弦，至少一根可弹奏。自定义资料可选填手指编号和横按品位、起止弦、手指编号；手指编号只允许 1–4，分别为食指、中指、无名指、小指。
- 图示、参考音和检测使用同一份指法数据。内置 Am 验收指法为 x、0、2、2、1、0，发声音为 A2、E3、A3、C4、E4；C 验收指法为 x、3、2、0、1、0，发声音为 C3、E3、G3、C4、E4。其余内置指法使用固定开放指法，不在不同模块维护不同版本。
- 手指或横按资料与弦品位明显冲突时禁止保存和导入，指出具体位置；例如不弹或空弦却带按弦手指、横按覆盖弦低于横按品位、编号超范围。覆盖弦在横按品位以上可有独立按弦，校验不得误拒绝此情况。不评估人体工学。更细的资料表示在实现时固化为共享校验规则，不增加指法优劣评分。

| 编号 | 行为约束及验收标准 |
| --- | --- |
| C01 | 十个内置和弦及自定义和弦均可查看指法图、试听和作为检测目标；高把位指法能辨认实际品位，横按以横条表达。 |
| C02 | 手指编号默认显示，可关闭；自定义未填编号时仅显示位置。左手镜像默认关闭，开启后保留弦号；数据顺序、音高和检测顺序不变。 |
| C03 | “播放和弦”从第 6→1 弦快速依次发声，跳过不弹弦；点击指法图的某根可弹奏弦只播放该弦目标音。界面标明“合成参考音”，采用一种清晰、音高准确的合成拨弦音色。 |
| C04 | 新增、编辑、复制、导入遇同名均保留已有资料，自动给新名称增加不冲突后缀；多条同名和连续导入仍保证名称区分，如 C（导入）、C（导入 2）。 |
| C05 | 导入仅接受本应用 JSON，可含多条；先校验整份，任一条无效则不写入任何条目，指出具体条目与原因。手指及横按资料同样校验并保留。 |
| C06 | 一键导出全部自定义和弦，文件可由同一入口重新导入；不把十个内置和弦作为自定义资料重复导出。 |
| C07 | 删除自定义和弦前确认，取消不改变资料；删除不影响历史记录。内置和弦没有直接删除或编辑能力。 |
| C08 | 新增、编辑、导入写入失败，原资料与未保存内容保留，无部分导入；明确标记未保存，提供重试或导出待保存内容入口。 |

### 逐弦和弦检测（Q1、Q18–Q22、Q26–Q27、Q51、Q59、Q66–Q67）

- 一轮开始时固定目标和弦及指法快照、基准音；沿第 6→1 弦只检查应发声弦。练习期间基准音不可修改，完成或退出后解锁。
- 状态为：未开始 → 当前弦等待有效单音 → 当前弦已有有效结果 → 用户下一弦／重测 → 所有应发声弦已有结果 → 用户完成 → 整轮结果及保存状态。中断或退出走放弃分支，不生成部分记录。
- 有效稳定输入定义为连续 300 毫秒音名和八度一致、音高波动不超过 10 音分；这 300 毫秒计入从清晰单弦弹奏到结果的 1 秒内。忽略拨弦瞬间的短暂波动。

| 编号 | 行为约束及验收标准 |
| --- | --- |
| D01 | 不弹弦显示“不弹／未检测”，不参与正确弦数或待完成数量，不验证消音。 |
| D02 | 未得到稳定单音显示“等待弹奏／请单独重弹”，不判为错音、不推进、不允许仅凭等待完成该弦。 |
| D03 | 有效输入须匹配目标八度，且偏差在 −20 至 +20 音分内，含边界，才显示“音高符合目标”；否则显示“音高不符”。不提供容差设置。 |
| D04 | 对错结果都停留当前弦，由用户点击“下一弦”；重测以最近一次有效结果为准，不因一次无效声音把结果改成错音或自动前进。 |
| D05 | 所有应发声弦均有有效结果后才允许“完成”；点击完成才保存一条记录，有错音也可完成；重复触发不得为同一轮创建多条记录。 |
| D06 | 中途退出、切换目标、切至调音器、麦克风异常或进入后台均放弃未完成本轮，不保存部分记录，明确提示本轮不会保存或本轮未保存。 |
| D07 | Am 和 C 按各自目标逐弦检查，能识别两套指法中不同的目标音；同名异八度输入必须判不符。不得把检测结果表述成实际手指或手型已验证。 |
| D08 | 显示当前目标弦、目标音、当前检测状态和整轮进度；结果页逐弦展示本轮结果，明确区分已完成检测与记录已保存。 |

### 音频协调、权限及生命周期（Q30、Q37–Q40、Q47–Q48）

| 编号 | 行为约束及验收标准 |
| --- | --- |
| A01 | 调音器与逐弦检测互斥占用麦克风；启动一个时停止另一个。停止检测时释放麦克风资源。 |

### 本地数据、设置与文件契约（Q11–Q17、Q26、Q46、Q53–Q56）

- 集中管理 localStorage 读写。自定义和弦及练习记录具有稳定 ID，预留同步状态和删除标记的扩展位置即可，不实现同步协议、网络请求或冲突自动合并。
- 和弦与记录使用独立 JSON 文件和独立入口。格式不兼容或记录格式版本不受支持时整份拒绝并说明原因；和弦格式与记录格式不能误用。具体 JSON 键名及可下载示例在实现文件读写能力时固定，不在本规格承诺未验证的库 API。
- 和弦文件携带名称、六弦状态及可选手指和横按资料；本地和弦身份使用稳定 ID，导入不得用文件中的身份覆盖已有条目。和弦同名规则与记录按 ID 去重规则互不混用。
- 每条练习记录保存稳定 ID、练习时间、目标和弦名称及当时指法、当轮基准音与各弦结果。结果足以重现逐弦符合／不符／不弹状态；推荐保留有效实测音高及偏差以支持详情查看，但不保存录音。
- 练习记录备份必须包含格式版本及上述记录数据。练习时间保留可排序的时间值，展示为用户可理解的本地时间。
- 设置包括 A4 基准音、左右手方向、手指编号显示、节拍器 BPM、拍数、细分、声音开关；下次打开恢复，恢复不启动功能。未确认的细分默认值不作为产品验收硬约束，实施时采用有效档位并在首次使用保持一致。

## Testing Decisions

### 测试边界与原则

2026-10-25 用户确认：以浏览器用户流程作为主要测试边界，真实麦克风和节拍时序另做实测。仓库当前没有测试框架、类似测试或可复用测试接口，不编造既有测试先例。

- 浏览器测试从可见入口操作，验证读数、状态、可用操作、记录与下载／恢复后的用户结果；避免测试组件内部状态、私有函数调用或存储键名。
- 主要流程覆盖调音器、节拍器、和弦库、逐弦检测、设置与记录的完整协作，不为每个内部模块建立独立测试入口。
- 需要可重复音高输入时，在浏览器音频输入边界使用可控单音；只用于确定性行为检查，不替代真实麦克风验收。不要求新增生产环境测试面板。
- ±5、±20、±100 音分及八度边界、整份导入事务、ID 冲突等难以靠实弹精确复现的条件，可在共享规则／读写公开边界补充最少量参数化测试；不因此拆出更多产品接口。
- 只验收外部行为。模拟权限或写入故障时，仍从用户结果检查资源停止、提示、保留内容及数据未被部分修改。

### 真实设备音频与节拍验收

- 正式浏览器：测试时当前稳定版 Chrome，覆盖 iPhone、Android、macOS、Windows。记录实际系统、Chrome 版本、设备与麦克风型号，不将桌面结果外推为手机通过。
- 环境：安静室内；钢弦与尼龙弦原声吉他；手机内置麦克风、电脑内置／外接麦克风。覆盖这些设备及输入类别并记录组合，不宣称保证全部机型。
- 每个音频测试项重复 10 次，至少 9 次须在清晰单弦弹奏后 1 秒内得到正确稳定结果；无法识别计未通过。稳定门槛为连续 300 毫秒音名和八度一致、波动不超过 10 音分，并计入 1 秒。有效错音应得到“音高不符”，不能把错音测试的通过定义为符合目标。
- 样例矩阵包含六根标准空弦（重点 E2）、Am 与 C 的各应发声弦、正确音与错音（含错八度）、高把位样例；高把位至少覆盖第 24 品极值。以 A4 = 430、440、450 Hz 核对可选基准与目标换算，设置步长另按浏览器行为验证。
- 响应计时从实际拨弦开始到界面出现有效结果结束，保存可核查的计时证据；不能只用音高检测回调时间替代用户端响应。
- 节拍器在前台以 30、80、240 BPM 各运行 60 秒，至少以十六分细分覆盖各速度。对比首个 click 至各预期节拍的实际发声时刻，累计时间偏差不超过 100 毫秒；检查漏拍、连发及视听对应。只查看定时器回调或预排播放时间不足以证明实际声音通过。
- 同时验证关闭声音的视觉节奏、下一小节参数切换、后台暂停及手动从第一拍恢复。视觉与声音对应按逐拍／逐细分观察记录，未约定额外的视听延迟数值门槛。
- 真实设备报告至少记录：测试项、设备／输入、基准、目标与实际结果、每次响应时间、稳定条件、10 次通过数、问题及证据。未测试标为未验证，不能写为通过。

### 实施与验收顺序

1. 等待用户明确“开始执行”，本规格和 `ready-for-agent` 不构成开始实现的授权。
2. 授权后先验证指定音频库的手机 E2、六弦覆盖、高把位、可选基准及 1 秒响应，再全面实现界面；节拍时序也必须实测。
3. 如音频无法达标，提交实际结果、失败条件及可选方案，与用户确认后才调整音频库或验收范围，不静默降低标准。
4. 完成浏览器行为、文件往返及失败恢复验收；正式设计尚未到位不阻塞这些工作。
5. 设计稿确认后完成视觉对齐与正式视觉验收，再确认总体交付。静态设计稿和合成输入测试均不能代替真实功能验收。

## Out of Scope

- 用户系统、登录、后端、数据库、账号或云同步、自动迁移、冲突自动合并。
- 曲谱展示、TAB 渲染、自动生成曲谱、曲目管理、AI 对话教练、学习路径推荐。
- 摄像头、手型姿态识别、真实手指或横按动作验证、实际发声弦／品位定位、消音效果验证、整把扫弦多音识别。
- 非标准调弦、变调夹、自动选目标弦、可调检测容差、多种参考音色。
- 其他软件文件格式、图片识别或谱站链接导入；恢复记录时自动补建和弦。
- 调音或节拍的练习记录、麦克风录音存储、趋势图、排行榜、练习评分、回收站及撤销。
- 原生手机应用、后台持续收音或持续节拍；Safari、Edge、Firefox、应用内浏览器不列为必须通过项。
- 电吉他直连声卡、失真效果器或嘈杂环境下的准确率保证；真实吉他音色的逼真还原。
- 本次不写应用代码、不建立测试工程、不安装依赖、不执行音频能力验证，也不把视觉探索中的搜索、滑块等附加控件自动转为新增功能要求。
